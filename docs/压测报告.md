# 压测报告：优化前后对比（传统直扣 DB vs Redis+MQ）

> 测试环境：Windows 单机 / Spring Boot 3.2 内嵌 Tomcat / MySQL 8.0 / Redis / RabbitMQ 3.13
> 测试工具：`scripts/load-test.ps1`（PowerShell 并发客户端）
> 测试场景：N 个独立用户在开售期内同时抢同一票档

## 一、两种方案说明

| | 方案A：传统直扣 DB（`POST /api/order/direct`） | 方案B：Redis+MQ（`POST /api/order/seckill`） |
|---|---|---|
| 校验 | DB 行锁扣减 | Redis Set 去重 + Lua 原子扣减 |
| 下单 | 请求线程内同步落库 | MQ 异步落库（削峰） |
| 售罄请求 | 抛异常 → 统一 500 | 业务码 400"该票档已售罄" |

## 二、实测数据（200 用户 / 50 张票 / 并发 50）

| 指标 | 方案A 直扣DB | 方案B Redis+MQ | 结论 |
|------|------------|---------------|------|
| 成功下单 | 50 | 50 | 两者都精确卖 50 张 |
| 售罄拒绝 | 150（以 500 异常形式） | 150（业务码 400） | B 对用户更友好 |
| QPS | ≈208 | ≈271 | **B 提升 ≈30%** |
| 平均响应 | 138.5ms | 54.7ms | **B 降低 ≈60%** |
| P99 | **376ms ❌ 超标** | **124ms ✅ 达标** | B 满足 PRD（P99<200ms） |
| DB 压力 | 200 次行锁竞争 | 50 次顺序写入 | B 削峰后 DB 从容 |

## 三、防超卖验证

- `scripts/load-test.ps1 -Users 100 -TierId 1 -Stock 20`
- 结果：**恰好 20 单成功**，DB 库存 100→20 后精确归零，Redis 库存精确归零，订单数=成功数
- 双保险机制：Redis Lua（判断+扣减原子执行）+ DB `UPDATE ... WHERE stock > 0`

## 四、JMeter 压测（500 并发验收）

```powershell
# 1. 生成压测用户 CSV
cd scripts
.\gen-users.ps1 -Count 500

# 2. 运行 JMeter（需已安装 JMeter 5.x 并配置 bin 到 PATH）
jmeter -n -t seckill-test.jmx -Jcsv=users.csv -Jthreads=500 -Jrampup=10 -JtierId=1 -l seckill-report.jtl
```

查看报告：`jmeter -g seckill-report.jtl -o reportHtml` 生成 HTML 报告。

> 说明：本机客户端为 PowerShell（HTTP 连接开销大），实测 QPS ≈ 270 为客户端瓶颈下的数值；
> JMeter 使用 Keep-Alive 连接池，QPS 通常可达 2000+。接口侧单次请求仅做
> Redis 读写（无 DB 访问），理论容量远高于实测客户端瓶颈。
